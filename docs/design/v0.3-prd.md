# Product Requirements Document (PRD)
## agent-sessions-obs v0.3：全栈 TypeScript 与 React 组件化重构（Bun 驱动）

* **版本**：v0.3.0
* **核心工具链**：**Bun**（装依赖、直接跑 TS、打包前端和 CLI、跑测试）
* **状态**：已实施
* **发布形式**：npm 包 `agent-sessions-obs`（`npx agent-sessions-obs` 与 `bunx agent-sessions-obs`）

---

## 1. 为什么这样改

1. **一个工具包办**：Bun 同时负责装依赖、直接运行 TS、打包前端（HTML 入口）、打包 CLI、跑测试。不需要 pnpm、tsup、tsx、Vite。
2. **开发用 Bun，用户用 Node**：CLI 用 `bun build --target=node` 打成单个 ESM 文件。用户机器只要有 Node 18+ 就能跑。

---

## 2. 技术选型

| 层次 | 选型 | 理由 |
| :--- | :--- | :--- |
| 运行与打包 | **Bun ≥ 1.2** | 装依赖、跑 TS、打包前端与 CLI、跑测试，一个工具。 |
| 语言 | **TypeScript 5.x 严格模式** | 前后端共用一份数据契约（`src/shared/types.ts`）。 |
| 前端框架 | **React 19** | 顶栏、进展、地图、抽屉、历史拆成组件。 |
| 前端打包 | **Bun HTML 打包** | Bun 能直接打包 HTML + TSX + CSS。Vite 只多出热更新和代理，本地小工具用不上，不引入。 |
| 样式 | **原 CSS 文件** | 原样式已过两轮设计验收，搬成独立 `styles.css`。改写成 Tailwind 没有用户可见收益，还有走样风险，不引入 Tailwind 和 Lucide。 |
| CLI 产物 | **Node ≥ 18 ESM** | `bun build --target=node`，只用 `node:http`、`node:fs`、`node:child_process`。 |

### 与初稿的差异

* **不用多包工作区**：只发布一个 npm 包，共享的只有类型。单包 + `src/shared` 目录就够，省掉三套 `package.json` 和 `tsconfig`。
* **不用 Vite**：见上表。开发时前端 `bun build --watch` 自动重打包，后端直接托管打包结果，只开一个端口，不需要代理。
* **不用 Tailwind / Lucide**：见上表。
* **包名改为 `agent-sessions-obs`**：`agent-obs` 在 npm 上已被占用。

## 4. 工程规范

### 4.1 构建脚本

```json
{
  "dev:cli": "bun --watch src/cli/index.ts",
  "dev:web": "bun build src/web/index.html --outdir dist-cli/web --watch",
  "build:web": "rm -rf dist-cli/web && bun build src/web/index.html --outdir dist-cli/web --production",
  "build:cli": "bun build src/cli/index.ts --target=node --format=esm --outfile=dist-cli/index.js --banner='#!/usr/bin/env node'",
  "build": "bun run build:web && bun run build:cli",
  "prepublishOnly": "bun run typecheck && bun run build"
}
```

React 等全部放开发依赖：前端打包进静态文件，用户安装时不下载任何依赖。

### 4.2 静态托管

* CLI 读取与自身同目录的 `web/`；开发时从 `src/cli` 运行，改读 `dist-cli/web`。
* 命中文件按扩展名返回；路径必须留在 `web/` 内；其余非 `/api` 请求回退 `index.html`。
* 未打包前端时首页返回 503，提示先运行 `bun run build:web`。

### 4.3 业务硬规则（不变）

严格继承 `docs/design/astra-review-v2.md`：
1. **机制不画**：派发、挂哨兵、等待、收束不建卡，只以 `sig: [{verb, agent}]` 署名出现在结果卡上。
2. **代理是署名不是泳道**：全图一条解决路径主线，不按 agent 分泳道。
3. **节点与动词边**：
   * 节点：`goal`, `subgoal`, `change`, `risk`, `verify`, `concl`, `gap`, `group`
   * 动词边：`拆成`, `采用`, `妨碍`, `解决`, `检查`, `支持`, `留下缺口`
4. **诚实原则**：未知直接建 `gap`，失败记录永久保留，不展示完成百分比或倒计时。
