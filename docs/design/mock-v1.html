设计说明（本页即渲染器规格）
  • 泳道 × 主线收束：主 agent 永远占据中央主干道，sub agent / Herdr 并行 agent / 后台哨兵各占一条侧道；紫色边 = 派生（fork）与收束（merge），所有侧道最终以紫色边汇回主线的「收束」节点 —— 这就是「树收束回主线」的显式表达。
  • Episode 压缩：节点不是 tool call，而是「意图 + 结果」的回合（如「回归门：8 条 10 秒片」），由规则粗切 + LLM 聚合产生，全图节点数硬上限 20。
  • 回路即卡点：红色虚线回边 = 重试/失败回路（如 p4 →p3 「修复后重跑」）；m8 → p4 的淡色虚线是「结果不变门 FAIL 回流」，表示收束之后仍可能打回开发道。
  • 实时更新 = 幂等快照：每次同步只是对 transcript 重新跑一遍同一管线，新 episode 就地淡入、状态就地变色 —— 不存在增量对账问题。右上有「模拟同步」可预演 4 个观察时刻。
  • 可溯源：每个 episode 挂着证据（原 JSONL 行号区间 / 产出文件），点节点即 drill-down，图与原始记录之间永远可对账。
  • 本页零依赖（无 CDN / 无构建），真实实现目标同样为单文件 CLI + 零依赖 HTTP server，只读 ~/.claude/projects。
