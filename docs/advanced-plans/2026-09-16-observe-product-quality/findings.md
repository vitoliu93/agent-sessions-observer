# 产品不足与修复清单

## 大前提

合格的地图要保留解决路径、来源与当前缺口，不能只把卡片塞进首屏。

## 小前提

接手基线 658ecff / index.html 730 行。独立浏览器对当前真实 API 的只读快照实测：1920×1080，无横向溢出，卡内部无溢出；但目标卡 x=788px（应在第一列），与折叠入口重叠；16 张业务卡只显示 5 张含目标、1 条边；5 秒轮询后 activeElement 从 c-GOAL 变为空。

证据：`/tmp/observe-acceptance/baseline.json`、`baseline.png`。后端历史和校验缺陷暂以源码为证，补充隔离红绿测试后才标已复现。

| Q16 | 子代理匹配按片段/名称/大小猜测，可能误配或漏配 | 待后端审计；精确 ID 优先，候选歧义显式报告 |

### 应该优化

- O01 核心事实由“未/错”等字决定，已解决风险也可能长期占首屏；状态与事实范围同时可见，不用关键词替代结论。
- O02 过程展开体覆盖其它卡，live 就地展开让整张地图跳位；统一详情阅读，不另加遮挡浮层。
- O03 长标题、长路径、200% 字体、较窄窗口需要可恢复布局，不靠缩字。
- O04 错误/截断/旧摘要没有清晰层级；时间戳要区分读到原始数据与摘要完成。
- O05 原文件缺可重复测试；需要隔离的 JSONL、输出规范、HTTP 与浏览器行为测试。

### 明确边界

不做多会话对比、云服务、账号或看板。模型概括可能出错，不能把归纳写成原始证据；无法定位的子会话、被裁切内容与缺失历史必须如实呈现。

### 已知限制

- 模型每次归纳粒度不同：同一会话一次 11 张修改卡，另一次 0 张。地图结构依赖模型，不能当作逐条日志。
- 模型仍会偶尔输出非 JSON 或错结构，靠拒绝 + 退避重试兜底，会多耗一次调用。

- 会话标题：Claude Code 取 custom-title/ai-title；Codex 取 session_index.jsonl。切换器显示标题 + 短 id。
- Codex 会话：~/.codex/sessions 与 archived_sessions；子 agent 按 parent_thread_id 精确挂载；前缀只匹配用户主线程（UUIDv7 前 8 位是时间戳，易撞）。真实会话 01a0a985：25 卡、3/3 子 agent exact-parent-id、18/25 证据可定位。
