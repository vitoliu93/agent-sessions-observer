# Agent Session 观察台：信息密度与交互把关

## 大前提

地图应先让人看清“解决到哪一步、谁在做、还差什么”，再允许人查看依据。**完整信息应该能找到，不应该同时摊开。**

## 小前提

根据本次提供的数据，24–42 张卡、16 个子 agent、30–52 条关系都进入同一张图；卡内又同时放标题、说明、全部事实和步骤。17/17 卡发生内部截断，说明问题不只是卡片高度，而是概览与全文没有分开。

本方案依据提供的结构和实测数据制定，未检查线上页面或源码。下列像素值是可直接落地的起点，最终以真实会话、浏览器排版验收。

## 结论

**P0 先减少同时展示的信息，不先做缩放。默认展示当前需求的关键解决路径；全文进入抽屉，历史分支折叠，边按选择显示。禁止靠缩小字体和列内滚动容纳全部内容。**

六类节点、目标归属、按职责署名、证据范围保持不变。折叠只是显示方式，不能删数据，也不能把未知写成成功。

# P0：必须改

## P0-1｜卡片只留四层，全文只在抽屉展开

### 具体做法

概览卡固定信息顺序：

1. **类型 + 状态**：一行，例如“验证 · 未通过”，不能只有状态点。
2. **标题**：最多 2 行，写具体工作或结果。
3. **核心事实**：最多 2 行，只放一个决定性结果或缺口。删除与标题重复的 `sub`；不直接展示整个 `facts ul`。
4. **职责署名 + 详情入口**：一行，例如“实现：P1　详情 · 6 条事实”。多人显示一个明确署名和“另 2 人”，完整职责分工进入抽屉。

`facts` 和 `steps` 保持完整，只从卡片正文移入抽屉。分组卡显示“包含 7 项修改”“仍有 2 项待验证”，不在概览铺步骤列表。

```css
  min-width: 0;
  height: auto;
  padding: 10px 12px;
  display: grid;
  grid-template-rows: auto auto auto auto;
  gap: 6px;
  /* 删除固定 height/max-height 和父级 overflow:hidden */
}
.card__meta { font-size: 12px; line-height: 18px; }
.card__title {
  margin: 0;
  font-size: 15px;
  line-height: 20px;
  min-height: 40px;
}
.card__fact {
  margin: 0;
  font-size: 13px;
  line-height: 18px;
  min-height: 36px;
}
.clamp-2 {
  display: -webkit-box;
  -webkit-box-orient: vertical;
  -webkit-line-clamp: 2;
  overflow: hidden;
  overflow-wrap: anywhere;
}
.card__footer {
  min-width: 0;
  display: flex;
  align-items: center;
  gap: 8px;
  min-height: 20px;
}
.card__author {
  min-width: 0;
  overflow: hidden;
  text-overflow: ellipsis;
  white-space: nowrap;
}
.card__details { flex: none; margin-left: auto; }
```

两行限制只作用于标题和摘要，不能套在整卡上。类型、状态、详情按钮、失败数不能被裁掉。长命令、URL、文件路径不要成为摘要正文。

核心事实不是从全文机械取前两行，应优先选：未解决问题 → 当前结果及其范围 → 等待的证据。没有可靠摘要就写“尚无结果”，不要生成一个乐观结论。

涉及限制条件时，把它放在句首，例如“仅 30 秒样本：118s”；不能让“仅验证样本 A”落在被省略的尾部。

### 展开位置裁决

| 操作 | 行为 |
| --- | --- |
| hover / 键盘聚焦 | 高亮卡片及直接关系，不扩高卡片、不弹全文 |
| 单击卡片 | 选中并突出相关路径；卡片大小不变 |
| 点击“详情”或选中后按 Enter | 打开右侧抽屉，显示完整事实、步骤、署名和来源 |
| Esc | 关闭抽屉并把焦点还给原卡；再次 Esc 清除选中 |

抽屉宽度 `480px`，`max-width: calc(100vw - 32px)`；标题区固定，正文单独纵向滚动。默认作为覆盖层，不挤压五列，也不触发全图重排。允许遮住部分图，因为这时用户已进入阅读模式；关闭后恢复原视角。

**为什么：** 一张卡只承担一次判断，详情按钮明确告诉用户“还有内容”，不再让隐藏溢出冒充完整信息。

## P0-2｜默认概览回答三个问题，不展示所有卡

### 具体做法

顶部从上到下：

- **目标条**：当前需求、明确的验收条件；多个需求用选择器切换，旁边显示其他需求的未解决问题数，不默默忽略其他需求。
- **当前进展条**：正在做什么、已证实什么、还差什么，具体见 P0-6。
- **地图**：目标 → 子目标 → 修改与问题 → 验证 → 结论。修改与问题仍是两种语义，只共用中间区域。

默认概览每个 zone 最多放 **3 张具体卡 + 1 个折叠入口**，不是把 42 张卡缩成 42 个小方块。显示的具体卡优先级：

```js
// 只对当前目标下的卡排序；同等级保留原来的稳定顺序。
priority = [
  '未解决障碍或相互冲突的证据',
  '进行中的工作',
  '决定目标是否达标的最新验证或结论',
  '其余记录'
];
```

超过 3 个未解决问题时，折叠入口必须写清“另有 5 项，其中 3 项未解决”，而不是“更多”。顶部仍显示总问题数。优先级不允许伪装成“只有三件事在做”。

概览只显示已知关系。若折叠导致证据链不完整，用“相关验证另有 4 项”说明，不能补一条不存在的直连边。

“查看本分支”进入该子目标的关系图，不变成任务列表；“返回概览”保留之前的选中和滚动位置。全文阅读另由抽屉负责。

**为什么：** 5 秒内看懂靠的是选择重要信息，而不是同时读完几十张卡。

## P0-3｜超过 8 张不做列内滚动：按解决路径折叠

### 具体做法

**选择折叠，否决每列独立滚动，否决自动缩小卡片。** 概览从第 4 张开始就需要收起；单 zone 超过 8 张时，分支视图也必须分组。

分组依据按顺序使用：

1. 同一子目标下的一组修改与验证。
2. 同一问题的“失败 → 修复 → 重验”。
3. 已结束且不影响当前判断的历史记录。

禁止按“同一 agent”“同一天”“都是工具调用”打包。没有可靠归属的卡进入“归属待确认”，不能强行分配。

折叠入口不是第七类业务节点，而是带虚线边框的 UI 容器，显示：

> 排序稳定性 · 7 条记录  
> 2 条失败 → 修复 → 重验通过  
> 查看路径

只有证据明确对应时才能这样总结。否则显示“含 2 条失败记录，是否解决待确认”。容器用“记录数、状态分布”描述内容，不产生独立业务结论。

点击容器后聚焦该分支，仍按“要求 → 做法/问题 → 验证 → 结果”排；跨分支依赖显示可点击的边界入口。分支较长时整张地图共用一条纵向滚动，不给五列各自设 `overflow-y:auto`。

```js
function presentZone(nodes, mode) {
  if (mode === 'overview') {
    const visible = chooseKeyNodes(nodes, 3);
    return { visible, folded: nodes.filter(n => !visible.includes(n)) };
  }
  return groupByKnownGoalAndIssue(nodes); // 仍过长时继续折叠次要历史
}
```

**为什么：** 各列独立滚动会让边指向看不见的卡；按问题折叠既减少数量，也保留“怎么解决”的结构。

## P0-4｜停止写死 x/y，用实际可见卡尺寸排版

### 具体做法

五列对应解决阶段，不对应代理。去掉 `goal:26 / subgoal:336 / ...` 这样的固定 x。卡片进入正常布局，SVG 覆盖在地图上，根据卡片实际位置画边。

```css
* { box-sizing: border-box; }
html, body { margin: 0; }
.app { min-width: 0; padding: 16px 24px; }
.map {
  position: relative;
  width: 100%;
  max-width: 1640px;
  margin-inline: auto;
}
.map-grid {
  display: grid;
  grid-template-columns: repeat(5, minmax(0, 1fr));
  column-gap: 32px;
  align-items: start;
}
.zone { min-width: 0; }
.zone-cards { display: grid; gap: 12px; }
.fold-entry { min-height: 64px; }
.edge-layer {
  position: absolute;
  inset: 0;
  width: 100%;
  height: 100%;
  pointer-events: none;

```

用 `ResizeObserver` 监听地图与卡尺寸变化，合并到一次 `requestAnimationFrame` 中更新边。通过 `getBoundingClientRect()` 减去地图矩形取得坐标；不要用猜测的卡片高度推进 y。

概览按 3 张约 152px 卡 + 64px 折叠入口 + 间隔计算，主体约 556px；目标条、进展条、列标题和留白合计控制在约 240px。1920×1080 下应能显示当前判断区和概览地图。

高度不足时，允许页面纵向滚动；不得压缩字高或裁掉底部卡。不要用 `body { overflow-x:hidden }` 掩盖布局错误，必须真正让页面宽度不超过视口。

**为什么：** 内容已经分层后，再让布局服从真实尺寸，才能从根上消除卡片被截和边线错位。

## P0-5｜边分三级显示，不让 52 条边同时抢注意力

### 具体做法

| 状态 | 显示的边 | 动词标签 |
| --- | --- | --- |
| 未选择 | 当前目标的主关系；其余淡化或隐藏 | 只显示最必要的 4–6 个标签，不重复铺满同一动词 |
| hover / 键盘聚焦卡片 | 该卡直接相连的边，其余变淡 | 显示该卡直接关系的标签 |
| 选中卡片 | 持续显示直接关系；保留通向目标的已知归属路径 | 重点关系显示标签；重叠的标签移到关系面板 |

**不能所有边都等 hover 才出现。** 默认图仍必须看得出解决路径，否则只是五列卡片。

```css
.edge--context { stroke: #cbd5e1; stroke-width: 1; opacity: .25; }
.edge--main { stroke: #64748b; stroke-width: 1.5; opacity: .65; }
.edge--selected { stroke: #2563eb; stroke-width: 2; opacity: 1; }
.edge-label { pointer-events: none; }
```

颜色仅示意；通过动词、箭头、实虚线辅助表达，不能只靠红绿。用深浅表示选中强度，不再用七种强色表示七种关系。

走线规则：

- 相邻列：卡片右侧锚点 → 列间空隙 → 目标卡左侧锚点，以折线或圆角折线连接。
- 跨多列：从列间空隙进入该子目标区域预留的上方或下方通道，再到目标列。预留通道高度随可见边数量增加，不能直接横穿中间卡片。
- 返回“问题”的修复关系走分支下方，不横穿标题或事实正文。
- 路径过密时，概览隐藏次要跨列边，显示“另有 3 条关系”；选择后再展开，不强求同时画完。
- 折叠组上的线只能表示“组内含这类关系”；显示数量，展开后恢复原端点。不同动词不合并成一条业务边。

标签沿空白段放置，浅色底遮线。测量标签矩形；碰撞则不放在图中，放进选中卡的关系面板，例如“检查 → 回归重跑”。每条关系都应能在文字面板中完整访问。

**为什么：** 默认看主线，选择后看关联，能保留地图价值而不把阅读变成找线游戏。

## P0-6｜live 三格限量，署名不再铺满一条横带

### 具体做法

live 保留三个固定问题，不用滚动字幕：

- **正在做**：最多显示 2 项，每项一句工作 + 一个明确署名。
- **已证实**：显示 1 项关键结果，附适用范围。
- **还差什么**：显示 1 项关键缺口；有更多则写“另有 N 项”。

```css
.live-grid {
  display: grid;
  grid-template-columns: repeat(3, minmax(0, 1fr));
  gap: 12px;
}
.live-cell { min-width: 0; padding: 10px 12px; }
.live-item { /* 使用 clamp-2，最多两行 */ }
.live-more { display: inline-flex; min-height: 24px; }
```

三个格子使用相同的信息预算，概览总高目标为 112–144px；不用 `height + overflow:hidden` 硬切。确实需要更多内容时，点“另有 N 项”打开进展详情面板，并能跳到对应卡。

16 个 agent 的全局入口改为：

> 参与者 16 · 正在工作 N · 等待 M　[查看]

N/M 只依据可证实的状态；无数据时写“状态未知”，不要推断在线。概览署名条最多显示 3 个当前工作者的 chip，另放“查看全部 16 人”，不显示一条超过容器的 12-chip 长串。

参与者面板可搜索，按具体工作分组展示角色、独立身份和职责。点击某人高亮其产出及关联目标。Reviewer、Programmer、不同 Task 身份不能因显示空间不足而合并署名；卡片上的“另 2 人”应能查到全部职责。

**为什么：** 用户首先需要“谁在做哪件事”，不是一份始终占据首屏的人员名单。

# P1：应该改

## P1-1｜选中态做关系阅读，不在卡内堆细节

### 具体做法

选中卡加 `outline: 2px solid`，其他无关卡降到 `opacity: .35`；相关卡保留清晰。地图下方或侧边提供短关系面板：“属于哪个目标、影响什么、由谁做、证据在哪”。面板不覆盖该选中卡。

点击关系条目定位并选中目标卡。已折叠的目标先展开对应分支，再定位。提供“返回上一个位置”，禁止用户沿关系点两次就丢失原位置。

卡片根元素可聚焦；方向键不是必做，但 Tab、Enter、Esc 必须可用。署名、详情按钮与根卡的点击事件分开，避免点详情时触发两次切换。

**为什么：** 选中态应该帮助用户沿因果和证据读图，而不是把一张卡变成更大的文章。

## P1-2｜实时更新冻结视角，不把正在读的卡挤走

### 具体做法

```js
if (userIsReadingBranch || drawerOpen || selectionId) {
  applyFactsAndStatusUpdates();       // 当前节点仍更新状态
  queueOverviewMembershipChanges();   // 新节点是否进入概览暂不重排
  showNewItemsButton(pendingCount);
} else {
  refreshOverviewWithStableOrder();
}
```

同等级卡保持原顺序，不按“最近更新时间”不断洗牌。新卡默认加入所属折叠组；只有直接影响当前目标的新失败、风险或完成证据，才更新顶部进展条并给“定位变化”按钮。

节点修改用 600ms 淡背景提示，遵守 `prefers-reduced-motion`。不自动平移、缩放、滚到最新内容。摘要暂未追上记录时显示“摘要更新中”，不要展示假实时。

**为什么：** 实时的价值是内容新，不是让页面一直动。

## P1-3｜密度切换值得做，但它应该切换信息量

### 具体做法

只提供两个模式：

- **概览，默认**：关键卡 + 按分支折叠，三张具体卡的预算。
- **展开当前路径**：保留其他路径折叠，只展开当前子目标及其相关问题、验证。

暂不做“舒适 / 紧凑 / 极简”三种字号档。需要新增紧凑档时，只减少间距和次要字段，不低于标题 14px、正文 13px，不改变状态与证据含义。

模式保存在当前页面状态；历史回放使用同一分层规则，不因进入历史就突然显示所有卡。

**为什么：** 信息量切换直接解决过载；缩字只能把过载变得难读。

## P1-4｜给历史一个入口，不让历史占首屏

### 具体做法

历史滑杆默认收起为“实时 · 查看历史”。打开后才显示时间轴与滑杆；只重建该时点已知的卡、状态和证据关系。

进入历史后固定显示“历史视图 · 时间”与“回到实时”。实时新增记录只更新提示数，不混入历史画面。回放时仍可选卡、查看详情和展开分支。

**为什么：** 时间是查证工具，不应与当前需求进展争夺首屏。

# P2：可以不改

## P2-1｜整体缩放暂不做

### 具体做法

保留浏览器原生缩放；页面内先不提供 25%–200% 连续缩放，也不做自动“全部适应屏幕”。验收必须在 100% 浏览器缩放下通过。

若后续全图探索确有需求，再提供可选的平移缩放模式：低比例时隐藏正文、只显示标题和状态；不能将普通卡全文整体压到无法阅读。该模式不作为默认入口。

**为什么：** 42 张全文卡缩到一屏仍然不可读，缩放不能替代信息筛选。

## P2-2｜小地图、边动画、代理头像墙不做

### 具体做法

不新增小地图、流动粒子、脉冲边和头像阵列。定位依靠目标选择、分支入口、署名筛选与“定位变化”。

**为什么：** 这些元素增加视觉刺激，却不增加对“是否解决”的判断能力。

## P2-3｜不必为了此次改造换图引擎或改六类语义

### 具体做法

继续使用原生 JS/CSS/SVG。增加一层显示数据：

```js
const viewState = {
  mode: 'overview',
  goalId: null,
  branchId: null,
  selectedNodeId: null,
  drawerNodeId: null,
  participantId: null,
  historyAt: null,
  expandedGroupIds: new Set()
};

// 原始节点、事实、署名、边保留不变。
// 此函数只决定哪些内容显示、哪些折叠，以及边映射到哪个可见入口。
const visibleGraph = projectGraph(sourceGraph, viewState);
```

折叠组单独保存在显示数据中，不写回业务节点类型；折叠不改变验证结论、不删除失败、不重写署名。

**为什么：** 当前瓶颈是展示规则，不是技术栈或节点分类。

# 交付验收门槛

以下是上线前必须复跑的检查，不是本报告声称已完成的测试。

| 检查 | 通过标准 |
